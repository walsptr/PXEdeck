Lokasi: infra/deploy-dashboard.sh:121-125 (sejak 4f958af, M6-T7; ada di m6-approved):

    {
      printf 'PXE_ADMIN_USERNAME=%s\n' "$ADMIN_USERNAME"
      printf "PXE_ADMIN_PASSWORD_HASH='%s'\n" "$admin_hash_val"
      [[ -z "$booting_min" ]] || printf 'PXE_JOB_BOOTING_TIMEOUT_MIN=%s\n' "$booting_min"
    } | ssh_server "umask 077 && cat > '$remote_stage/admin.env'"

Di dry-run (INFRA_DRY_RUN=1) `ssh_server` -> `run` hanya mencetak baris `DRY-RUN: ssh ...` dan keluar
TANPA membaca stdin. Bila sisi kanan pipe sudah keluar sebelum blok `{ printf ...; }` menulis, printf
mendapat SIGPIPE (exit 141). Dengan `set -euo pipefail` pipeline bernilai 141 -> deploy-dashboard.sh
mati -> kvm-run.sh gagal di tahap `deploy` dengan `result FAIL exit=141 stage=deploy`. Ini race
penjadwalan murni (siapa duluan: penulis atau pembaca pipe), jadi jarang dan tidak bisa direproduksi
sesuka hati tanpa mengubah timing. Di run KVM nyata `ssh` membaca stdin sehingga jalur non-dry tidak
terkena (kecuali ssh gagal sebelum membaca — lalu toh sudah gagal).

Mengapa justru test AC-7.17 yang terlihat flaky: test ini menjalankan kvm-run.sh dry-run EMPAT kali
(vlansmoke, vlanneg, vlancore, vlandistro), masing-masing melewati deploy-dashboard.sh, dan
`assert_eq "$RC" 0` langsung gagal pada exit 141. Test lain yang menjalankan kvm-run/deploy dry-run
(run.sh: test_kvm_run_dry_run_end_to_end, test_deploy_dry_run_no_secrets, m6.sh, m7-infra.sh
skenario VLAN, m7-te.sh, dst. — ~50 pemanggilan run_infra kvm-run/deploy) sama rentannya; peluang per
test sebanding dengan jumlah pemanggilan deploy dry-run di dalamnya.

- Timestamp/run id: run id dari skenario (bukan waktu); PXE_RUNS_DIR dihapus+dibuat ulang tiap skenario.
- (Bahaya laten terpisah, BUKAN penyebab yang direproduksi:) dua `infra/test/run.sh` paralel di worktree

## Saran perbaikan (untuk backend-dev; perlu ditugaskan Orchestrator)
Di deploy-dashboard.sh, jalur dry-run tidak boleh mem-pipe ke perintah yang tidak membaca stdin, mis.
  if is_dry; then ssh_server "umask 077 && cat > '$remote_stage/admin.env'" </dev/null
  else { printf ...; } | ssh_server "..."; fi
atau `run()` di dry-run menguras stdin (`cat >/dev/null`) bila stdin bukan TTY/kosong. Test regresi yang
diusulkan: jalankan deploy-dashboard.sh dry-run dengan penulis lambat (mis. PATH printf/env palsu atau
hook delay) dan tuntut exit 0. Test AC-7.17 sendiri sudah benar dan tidak perlu dilonggarkan.
