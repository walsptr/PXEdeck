## Pemeriksaan

**Password / hash.**
- Hash dibuat server dengan `unixcrypt.encrypt` (SHA-512 crypt `$6$`) di `config-service.ts:304/324/345` (tidak berubah secara semantik dari M3). `context.ts:230` memvalidasi ulang format `$6$` sebelum masuk generator; Ubuntu `identity.password`, Debian `passwd/user-password-crypted`, Rocky `user --password=… --iscrypted` hanya memuat hash. Windows tidak memakai hash/password dari konfigurasi (lihat SR-4-3).
- `GET /api/hosts/:id/config` membuang `passwordHash` (`toPublicConfig`), `GET /api/hosts*` tidak memuat config. Satu-satunya `console.*` produk adalah `boot-http.ts:25` (tanpa token/hash).
- Screenshot sheet KVM (`kvm/attempt4-*/screenshots/*-sheet.png`) hanya menampilkan public key sekali pakai; Playwright `error-context.md` hanya memuat source harness (variabel `PASSWORD`, bukan nilainya).

**Token per job (DEC-008).** `tokens.ts`: 32 byte `randomBytes` → base64url 43 karakter; DB hanya `sha256` hex (`jobs.token_hash`), lookup lewat hash → tidak ada perbandingan string plaintext/timing. Token baru tiap script installer dilayani (`discovery.ts:324`), dicabut saat `done|failed` (`provisioning.ts:177`), TTL default 360 menit. Penolakan file/status → 404 seragam `not found`; 400/409 status callback hanya setelah otorisasi token+MAC+IP (`provisioning.ts:157-169`) → tidak ada oracle. Respons `no-store`.
**B-5.** Token tidak lagi tertulis di user-data/preseed/kickstart: `callbackUrlCmd` (`shell.ts:50-57`) menurunkan URL dari `/proc/cmdline` saat runtime dengan pola ketat (MAC host + 43 char). URL disimpan di target hanya di `/etc/pxe-callback/url` (dir 0700, file 0600 via `umask 077`) dan dihapus unit first-boot setelah `done`; `verify-ssh.txt` mengonfirmasi file & unit sudah hilang. Untuk Ubuntu, parameter `ds=nocloud-net;s=…` berada **sebelum** `---` (`boot-script.ts:111-121`) sehingga curtin tidak menyalinnya ke GRUB target. Sisa risiko kecil di SR-4-6/SR-4-7.

**Endpoint `/boot/**`.** MAC divalidasi `STRICT_MAC_RE` lalu dinormalisasi; token `TOKEN_RE`; nama file hanya dari peta konstan `INSTALLER_FILES` dengan `Object.hasOwn` → tidak ada path traversal (tidak ada akses filesystem dari segmen URL). Script iPXE: semua nilai lewat `ipxeSafe` (tanpa spasi/`$`/newline); `PXE_KERNEL_EXTRA_ARGS`/URL/path divalidasi di `settings.ts`.
**Injeksi template.** YAML lewat library `yaml.stringify`; preseed/kickstart lewat `singleLine`/`di` (CR/LF/NUL ditolak); XML lewat `xmlEscape` + tolak karakter kontrol; shell lewat base64 (`b64write`, path regex + tanpa `..`) dan `shQuote`; username/hostname/IP/DNS/TZ/locale/disk/repo divalidasi ulang di `validateContext`; komentar SSH key disanitasi. URL callback Windows dibatasi `CALLBACK_RE` (tanpa `'`) sebelum masuk string PowerShell bertanda kutip tunggal.
**SQLite.** Semua query `prepare(...)` dengan parameter `?`; interpolasi hanya nama kolom dari peta konstan (`hosts.ts:106`, `jobs.ts:132`) dan konstanta status. `resetDb` tidak diekspos sebagai route.
**Allowlist Host / `PXE_TRUST_PROXY`.** `guardMutation` kini menolak Host di luar `PXE_ALLOWED_HOSTS` (SR-3-5 tertutup). `X-Real-IP` hanya dipercaya bila `PXE_TRUST_PROXY=1`; deploy VM: Next `HOSTNAME=127.0.0.1` (diverifikasi `install-dashboard.sh:85-92`), nginx menimpa `X-Real-IP $remote_addr` dan mengosongkan `X-Forwarded-*`/`Forwarded`, access log menyamarkan segmen token.
**`infra/**`.** `assert_name` (prefix `pxe-test-` + daftar terlindungi `pxe-test-node01 ubuntu24.04 default int`), `assert_path_in_vms` (realpath = `.agent/vms`), `assert_mac`, run id `^[a-z0-9]+$`, variabel ter-quote; perintah remote lewat `bash -s` dengan validasi `RELEASE_TS`/`STAGE`; rilis disaring dari `.env*`/`*.db`. Tidak ada sudo; ssh hanya ke 10.99.0.2.
**Secret di repo & bukti.** `git grep -nE "BEGIN .*PRIVATE KEY|password\s*[:=]" HEAD`: hanya fixture/header palsu, teks laporan, kode generator, dan placeholder `@PXE_PASSWORD_HASH@`. I-3-14 (`$6$pxelab$…` + public key pribadi di `configs/autoinstall/user-data`) **sudah dibereskan** di HEAD (template + render dari env). `.env` tidak ter-commit (hanya `.env.example` dan `infra/server/dashboard.env`, keduanya tanpa rahasia); `.agent/keys|vms|media`, `*.db` di-ignore.
Pemindaian independen reviewer (script di scratchpad, bukan file repo): (a) seluruh file `.agent/runs/m4/**` — pola token `/boot/<mac>/<43>`, `$6$…`, `PRIVATE KEY`, password fixture, baik teks maupun blob base64 (UTF-8 & UTF-16LE, offset 0–3); (b) **setiap blob yang ditambah/diubah di semua commit `main..HEAD`** (535 blob, jadi termasuk versi bukti sebelum redaksi). Hasil: hanya fixture (`$6$fixturesalt$…`, `TOKEN_abc…`, `FIXTURE-token-not-real…`, header private key palsu) dan teks skrip/laporan; semua `nocloud-net;s=` di console sudah `<token>`/`REDACTED-TOKEN`. Selaras dengan `secret-scan.txt` dan `kvm/evidence-scan.txt` ("bersih"). Tidak ada token/hash/password nyata di repo maupun riwayat branch.
